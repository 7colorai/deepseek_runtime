# 已知未知（Known Unknowns）

> ❓ **"已知未知"是什么？**  
> 💡 这是美国国防部长拉姆斯菲尔德的名言框架——"我们知道我们不知道什么"。在软件工程里，就是**主动列出现有版本没有解决的问题**。坦诚比假装完美更有价值。

以下每一条，都是 v0.1.1a1 版本**故意不解决**的问题——不是忘了，而是有意识地决定留到以后。

## 为什么要把这些写出来？

❓ **别人都不会列"自己没做到什么"，你们为什么列？**  
💡 三个原因：

1. **信任**：告诉你没做什么，比让你自己去发现"原来这里没有"要好得多。
2. **决策**：如果你是 PM 在评估是否基于这个运行时做产品，你需要知道它在哪还没准备好。
3. **路线图**：每条"已知未知"都对应一个明确的"下次检查点"——不是空洞的承诺。

---

## 对 PM 的几点解读

- **成本估算 ≠ 真实账单**：如果你的产品计费依赖 Token 用量，运行时给出的成本估算只能做参考，不能用来开发票。
- **沙箱防不住决心要跑的代码**：当前沙箱防止的是"Agent 意外搞破坏"，不是"恶意代码逃逸"。多租户场景需要 OS 级隔离。
- **工具幻觉是"双层问题"**：运行时只负责把 DeepSeek 生成的 JSON 调令解析出来并找到对应函数。如果模型捏造了一个不存在的参数，运行时挡不住——这需要工具处理器自己做 Schema 校验。
- **模型名会变**：DeepSeek 官方改模型名（比如弃用某个版本）不会通知每个用户。保持冒烟测试和文档同步是你的责任。

## 相关引用

这些"已知未知"的坦诚记录方式，受到以下研究的启发：

- **Paper A1 — Agent Harness Survey**：该综述指出，**绝大多数 Agent 框架只宣传能力，不披露边界**。本运行时的"已知未知"文档是对这种"只说好话"文化的反向实践。
- **Paper B2 — Generative Agents (UIST 2023)**：斯坦福 AI 小镇的研究表明，Agent 系统在开放环境中的行为**不可穷举验证**。承认这一点是负责任工程的一部分。
- **Paper A3 / A4**：关于 LLM 行为建模的系统性研究指出，对一个模型做"完整特性覆盖"是几乎不可能的——主动界定范围比假装全覆盖更可靠。
- **Paper D1**：Agent 安全研究中反复强调，"本地沙箱不是安全边界"是一个经常被忽视的风险。本文档是对这一发现的直接响应。
- **Paper E1 / E2**：关于 LLM 成本估算误差的研究，为"真实计费准确性"这一条提供了数据支撑——估算和真实账单之间的差距可能远比你想象的大。
